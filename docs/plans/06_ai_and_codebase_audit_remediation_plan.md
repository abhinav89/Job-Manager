**Local development scope update:** At the user's request, Docker is optional for trusted local use. `EXECUTION_BACKEND=local` runs native Python and LaTeX with explicit development-only configuration and loopback server binding. This is not isolation and does not satisfy the P0 isolation acceptance checks. Those checks apply to the Docker backend retained for hosted deployments. Native mode is rejected outside development and is never an automatic fallback when Docker is unavailable.

## Goal

Remediate the findings from the 7-domain project audit across the AI layer, backend security, LaTeX/PDF compilation pipeline, database access patterns, and Next.js frontend. Ensure every AI workflow strictly upholds the domain invariants in [`CONTEXT.md`](../../CONTEXT.md) (Personal Evidence, Confirmed Skills, No-invention rule, Metric Prompts `[X]` handling, One-page rule, and no numerical fit scores) while eliminating critical security and concurrency bottlenecks.

## Audit baseline before remediation

- **LLM & Agent Layer:** All LLM JSON calls rely on prose instructions and regex fence slicing (`clean_json_response`) rather than native Structured Outputs (`response_schema`). In the Career Agent, [`assistant_routes.py`](../../ai-service/routers/assistant_routes.py) slices `user_evidence` from the tail (`[-20000:]`) while [`career_tools.py`](../../ai-service/services/career_tools.py) and [`llm_service.py`](../../ai-service/services/llm_service.py) slice from the head (`[:12000]`), dropping the newest 8,000 characters of user statements. [`career_agent.py`](../../ai-service/services/career_agent.py) flattens multi-turn history into a single JSON user message on an ephemeral `InMemorySessionService`.
- **Resume, LaTeX & Spot-Edit Pipeline:** [`latex_assembly.py`](../../ai-service/services/latex_assembly.py) injects `summary`, `certifications`, `education`, and `contact` fields without `_escape_latex()`, allowing `%`, `&`, `$`, `#`, or `_` to break compilation. [`spot_edit_service.py`](../../ai-service/services/spot_edit_service.py) reads `profile.skills` without filtering for `is_confirmed`, collides multiple roles at the same company, and includes `date_range` years in `allowed_numbers`. Preset `section_order` is ignored by [`latex_assembly.py`](../../ai-service/services/latex_assembly.py), so rendered headings can disagree with the requested order and produce misleading [`ats_check.py`](../../ai-service/services/ats_check.py) failures; the deterministic Preset × Template matrix below must establish the affected cases.
- **Security & Auth:** `POST /code/run` in [`code_service.py`](../../ai-service/services/code_service.py) runs untrusted Python via `subprocess.run` on the host with inherited environment variables and filesystem/network access. Raw LaTeX submitted through generation and tracker endpoints also reaches a host compiler in [`pdf_service.py`](../../ai-service/services/pdf_service.py); escaping generated resume text does not isolate this separate input path. `POST /tracker/fetch-job-details` in [`tracker_routes.py`](../../ai-service/routers/tracker_routes.py) fetches unvalidated URLs (SSRF) and passes up to 800,000 characters of raw HTML to the LLM. All `/generate/*` routes lack session authentication (`get_current_user_id`), and `POST /generate/compile` has no `return` statement.
- **Database & Concurrency:** [`assistant_routes.py`](../../ai-service/routers/assistant_routes.py) holds an uncommitted DB transaction open across 10–60s of synchronous LLM and Tectonic calls, starving the connection pool and blocking the FastAPI event loop.
- **Frontend UX:** In [`generate/page.tsx`](../../frontend/src/app/(authenticated)/generate/page.tsx), Spot Edit (`handlePdfSelection` and `spotEditLayer`) and multi-page navigation are only mounted in `"source"` mode, not in `"friendly"` or `"preview"` modes. Switching from `"source"` to `"friendly"` mode does not re-parse `draft`, and [`interview/page.tsx`](../../frontend/src/app/(authenticated)/interview/page.tsx) leaks the webcam `MediaStream` on unmount while re-rendering at 60 FPS.

Public URLs redirecting or resolving to internal IPv4/IPv6 destinations are rejected, and oversized/slow fetches stop within configured limits. Unauthenticated callers receive `401` on `/generate/*`, `/code/*`, and `/interview/*`; user A cannot generate or Spot Edit using user B's profile by supplying B's email. Authenticated `POST /generate/compile` returns a parseable PDF with the PDF content type. Auth/session regressions cover normalized email lookup, registration password validation, null-password login rejection, and non-remembered expiry.

## Dependencies and release checks

- PR 01 establishes the test baseline. Production exposure requires the P0 authentication and isolation boundaries in PRs 02–06; vulnerable execution must remain unavailable until its isolation checks pass. The compile-return fix can merge early, but does not establish safe raw-LaTeX handling by itself.
- The recent-evidence fix (PR 09) and Spot Edit grounding work (PR 10) can ship without waiting for the full Structured Outputs migration or ADK history redesign. The shared structured helper is required only for the workflows being migrated to it.
- PDF assembly and frontend editor changes share the LaTeX source-of-truth contract. Re-run the existing draft parser checks when section assembly or escaping changes, and verify that Spot Edits leave all unselected Blocks byte-identical.
- The transaction redesign (PR 14) requires an explicit request lifecycle and retry policy. The assistant cancellation UI (PR 19) follows it. Profile-loading and cleanup work can proceed separately, with short-lived Session ownership preserved when integrated.
- Each behavior-changing PR includes its regression checks and records the commands/results. Use deterministic provider fixtures for normal CI, provisioned compiler/sandbox checks for isolation and PDF acceptance, Postgres for concurrency guarantees, and focused browser checks for selection, media cleanup, and stale-response behavior. Live model smoke tests may supplement these checks but do not replace them.
- Before release, verify that fresh database initialization and upgrades support any request-lifecycle schema changes; run the deterministic Preset × Template matrix and the P0 isolation/access tests against the intended deployment configuration. Record configured execution/fetch limits and observed concurrency results.
