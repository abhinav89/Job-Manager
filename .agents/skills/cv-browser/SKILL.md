# cv-browser

This is optional setup. For application filling, first follow [cv-apply](../cv-apply/SKILL.md) and use working native browser/computer tools when they support the user's chosen browser/session. Do not install or configure this adapter merely because an agent uses Gemini, Claude, Codex or another model. Use it when native access is unavailable/incompatible, the user explicitly chooses its restricted interface, or the task resumes a session created by this wizard. A compatible native browser session needs no wizard or MCP setup.

Never request passwords, MFA codes, recovery codes, cookies or sign-in tokens in chat, files, command arguments or environment variables. Do not read browser profiles or use general browser tools to extract session state. The user types credentials directly into the visible sign-in browser.

Run `cv-tailor browser status`. If automation dependencies are missing, install `python -m pip install -e "ai-service[automation]"` using this repository's environment. Brave, Edge and Chrome use the installed browser; Chromium, Firefox and WebKit use Playwright builds installed with `python -m playwright install BROWSER`. Brave is discovered in standard Windows/macOS locations or on PATH; `CV_TAILOR_BRAVE_PATH` can specify its executable. Never silently substitute another browser when Brave is missing.

Keep setup out of the user's chat instructions. Determine the running agent host and project folder from the session, not the chosen model. Open `cv-tailor browser setup --agent AGENT --project ABSOLUTE_PROJECT` (or `browser login --site SITE` with those same flags for an existing site). Agent choices are `antigravity`, `gemini`, `claude`, `codex`, and `opencode`. The wizard preselects the app/project; the user only signs in, completes MFA/CAPTCHA, returns to the job page, and clicks **Save session and close browser**. It records a site name, browser, token-free start URL and exact allowed origins. The wizard and MCP server require exclusive ownership of that site's profile: disconnect its MCP server before signing in again.

Use the wizard's **Connect to my AI app** button, or run `cv-tailor browser connect --site SITE --agent AGENT --project ABSOLUTE_PROJECT` yourself after local sign-in has finished and its browser is closed. This saves one project-local server entry, preserves unrelated settings and rejects conflicting entries or a home/global target. Do not ask the user to copy JSON or edit settings when this supported path works. Have the user reload the connection/restart the app if required; do not claim it connected until the running host discovers the tools. Codex still requires a trusted project and hosts can require their own approval of project tools. Do not change trust, approval or global settings to bypass that.

Advanced/manual fallback: `cv-tailor browser mcp-config --site SITE` emits nonsecret standard MCP JSON, or use `--host opencode` for OpenCode's format. Existing JSONC or conflicting TOML layouts are left unchanged; use that host's connection manager instead of rewriting them. The tools are model/vendor independent and the server is `cv-tailor browser serve --site SITE`. Windows MCP must run `python.exe`, not `pythonw.exe`, even when the wizard itself runs without a console. Never modify another agent's global configuration.

For applications, follow [cv-apply](../cv-apply/SKILL.md). Prefer the restricted `cv-browser-SITE` tools for sessions created here. Export explicitly selected PDFs into `DATA_DIR/browser/uploads/SITE/` using their exact manifest filenames. Supply only that filename to `browser_upload`. Browser references expire after each observation; save semantic checkpoint identities separately. Native controls, exact option labels and file readbacks are supported; custom widgets may require local user action. There is no arbitrary JavaScript, screenshot, file-read, cookie, storage, network-log or password tool.

If a tool reports sign-in or a verification field, checkpoint application answers and open the local wizard. Never switch to unrestricted tools to inspect that sign-in session. Final consent and submission remain with the user. A user-saved session is not proof of authentication; verify the application page when tools resume.

The restrictions apply to this MCP interface. Browser profiles contain sensitive authenticated state. They are not isolated from other processes with the same OS permissions, unrestricted shells, or unrelated desktop-control tools. Do not promise that local storage makes credentials inaccessible to every AI tool. See [the browser setup documentation](../../../docs/browser_setup.md) for the actual boundary.
